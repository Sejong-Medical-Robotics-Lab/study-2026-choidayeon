# 학습일지 — 2026-08-14 (Week 4, Go2 실기체 키보드 조작)

## 오늘 배운 것
- 키보드 입력이 로봇을 직접 움직이는 게 아니라, `teleop_twist_keyboard`(입력 → `/cmd_vel` 발행) / `go2_nav_bridge`(`/cmd_vel` 구독 → Sport API `Move()` 호출) 두 노드로 역할이 분리되어 있다는 것
  ```
  키보드 입력 → teleop_twist_keyboard → /cmd_vel → go2_nav_bridge → Unitree Move API → Go2
  ```
- `go2_nav_bridge`가 없으면(즉 `/cmd_vel`의 Subscriber가 0이면) 키보드 입력이 정상적으로 나가고 있어도 로봇은 전혀 움직이지 않는다는 것 — 문제가 생겼을 때 "어디까지는 정상인가"를 토픽 발행/구독 여부로 나눠서 구분해야 한다는 것
- 새 터미널을 열 때마다 `source /opt/ros/humble/setup.bash` → `source setup.sh` → `source install/setup.bash` 세 번을 다시 적용해야 한다는 것(작업공간이 `~/Desktop/unitree_ros2`로 시뮬 실습 때와 분리되어 있음)
- 실기체는 Gazebo의 Reset World 같은 되돌리기가 없기 때문에, 정지 수단(`k` 입력 / 리모컨 비상정지)을 실행 전에 미리 확보해두고 시작해야 한다는 것

## 직접 해본 것 / 성공한 것
- 로봇 전원을 켜고 리모컨 Start 버튼으로 보행 가능 상태로 전환
- 터미널 1에서 `ros2 run my_go2_nav go2_nav_bridge` 실행해 브리지 노드를 띄운 상태로 유지
- 터미널 2에서 `ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -p speed:=0.5 -p turn:=1.0` 실행
- 실제 Go2를 키보드로 전진·후진·좌우 이동·회전시켜보고, `k`로 정지, `Ctrl+C`로 프로그램 종료까지 확인
- `go2_nav_bridge.cpp` 코드를 열어 `/cmd_vel` 구독 → `linear.x`/`linear.y`/`angular.z` 값 읽기 → `sport_client_.Move()` 호출로 이어지는 흐름을 직접 코드에서 짚어봄

## 막힌 것 / 이해가 안 되는 것 (다음 Q&A 때 질문할 목록)
- `speed:=0.5`, `turn:=1.0` 파라미터가 `teleop_twist_keyboard`가 `/cmd_vel`에 싣는 값의 상한인지, 아니면 브리지 쪽 `Move()`에서 다시 스케일링되는 값이 따로 있는지 코드까지는 못 봄
- 시뮬 스택 문서(`docs/real_robot.md`)에 있는 `/cmd_vel` 워치독(0.5초 끊기면 정지)이 실기체 브리지에도 동일하게 구현돼 있는지, 아니면 키를 계속 눌러야만 멈추지 않는 구조인지 확실하지 않음
- 리모컨 비상정지와 `k` 정지가 내부적으로 같은 경로(Sport API `StopMove`)를 타는지, 아니면 리모컨은 저수준에서 별도로 개입하는 안전장치인지 궁금함
