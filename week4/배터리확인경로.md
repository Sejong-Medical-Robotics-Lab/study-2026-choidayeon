# Go2 배터리 확인 경로

## 실기체 — DDS `rt/lowstate` → `bms_state`

`unitree_sdk2_python`(`~/unitree_sdk2_python`)의 IDL 정의를 직접 열어서 확인한
실제 경로. `LowState_` 안에 `bms_state` 필드가 있고, 그 타입이 `BmsState_`.

```
LowState_.bms_state : BmsState_
```

`BmsState_` 필드 (`unitree_go/msg/dds_/_BmsState_.py`):

| 필드 | 타입 | 의미 |
|---|---|---|
| `soc` | uint8 | 충전율(State of Charge, %) — 배터리 확인할 때 제일 먼저 볼 값 |
| `status` | uint8 | 충전/방전 등 BMS 상태 코드 |
| `current` | int32 | 전류(양/음수로 충전·방전 구분 추정) |
| `cycle` | uint16 | 충방전 사이클 수 |
| `cell_vol[15]` | uint16 배열 | 셀별 전압(15셀) — 밸런싱 이상 확인용 |
| `bq_ntc[2]`, `mcu_ntc[2]` | uint8 배열 | BMS/MCU 온도 센서 |

즉 실기체에서 배터리 확인 경로는:
```
rt/lowstate (DDS) → LowState_.bms_state → .soc (%)
```

## 시뮬레이션(go2_sim) — 배터리 자체가 없음

오늘/그동안 써온 `go2_edu_interfaces/msg/LowState.msg`를 직접 열어봤는데,
필드가 `tick` / `motor_state[]` / `imu_state` 셋뿐이고 **배터리 관련 필드가
아예 없음**. `go2-edu/docs/real_robot.md`의 실기체 세션 전 브리핑 체크리스트에도
"실제 보행 동역학·마찰·지연·**배터리**"가 시뮬↔실기체 차이 항목으로 명시돼
있어서, 이건 빠뜨린 게 아니라 **의도적으로 시뮬레이션 범위 밖**으로 둔 것으로
보임(교육 목표가 sport mode 관제 로직이지 전력계 모델링이 아니라서).

→ 그래서 지금 `~/go2_harmonic_sim`에 띄운 Go2에도 배터리 값은 없고, 배터리를
실제로 확인하려면 위 실기체 경로(`bms_state.soc`)를 금요일 실기체 세션에서
써봐야 함.

## 확인 방법 요약

| 환경 | 확인 경로 | 비고 |
|---|---|---|
| 실기체 | `LowState_.bms_state.soc` (DDS `rt/lowstate`) | unitree_sdk2py로 구독 |
| 시뮬레이션(go2_sim) | 없음 | LowState.msg에 배터리 필드 미존재 — 설계상 범위 밖 |
